# BDD / Cucumber

`transfer.feature` records candidate acceptance behaviours in Gherkin syntax.
These are specifications, not proof of executable Cucumber coverage.

Before claiming BDD execution:
1. Confirm the project's actual acceptance requirements and step semantics.
2. Configure compatible Cucumber dependencies and a test runner.
3. Implement step definitions using the real application APIs.
4. Run the scenarios and preserve the test output.
5. Link each scenario to the RTM and any defects it detects.

Until those steps are complete, status is **drafted; not executed**.
